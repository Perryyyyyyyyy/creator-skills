# 视频拆解与图文报告

目标是生成可核对的中文拆解报告，并在素材和处理能力允许时输出带时间码的文案与成片还原脚本。

本机已部署执行器 `D:/codexfile/mySkill/video-breakdown/run.ps1`，支持链接获取、本地视频校验、CPU 转写、关键帧、字幕和报告导出。运行前读取 [references/usage.md](references/usage.md) 并执行 doctor 检查实际环境。新增依赖、下载、模型和缓存保持在 D 盘。

执行器准备素材后，由当前助手阅读逐字稿和关键帧、撰写八角度分析，并通过 review 命令导入。命令行预处理完成不等于语义分析完成。公开主页可读时会补充粉丝显示值与简介；“1万+”之类区间保持原样。尚未接入自动 OCR、评论全量采集或 DOCX 导出；使用已有浏览器和文档能力补充时注明来源，不声称脚本内置这些功能。

## 输入和默认行为

接受视频链接、视频文件、字幕、口播稿和账号截图。优先使用用户指定的平台与输出格式；未指定时生成结构化 Markdown 主稿及内嵌图表的单文件 HTML 图文版。适用的完整逐字稿同时收录于主报告并提供独立附件；SRT 和 CSV 分镜按需要交付。

用户要求修改已有报告时先读取现稿和任务记录，只修改相关内容；不要为版式、图表或文案整合而重做已完成的下载与转写。保留内部备份并同步主稿和阅读副本。

对链接和本地视频先运行本机执行器，而非重复浏览器截图尝试。使用明确任务目录便于恢复；模型准备好后加 --offline。run 退出码 2 代表部分完成，应继续查看 record.json 和素材完成分析，不将它当成全部失败。严格按当前素材使用范围决定是否交付全文转录。

新任务保存到独立输出目录。已有任务补充素材时先读状态，验证媒体指纹后继续，保留原始转写和来源证据。

## 核验与采集

- 对链接先读取实际笔记，记录标题、正文、作者、笔记 ID 和可见互动数；需要粉丝量时读取对应账号主页。
- 以可下载和可解码的实际媒体文件作为转写与抽帧基础。网页标题、单帧截图和正文均不能证明已观看全片。
- 使用当前可用的页面媒体、导出能力或经过验证的适配器。登录或访问受阻时保存进度，针对缺失项请求视频或截图；不要无止境重复相同超时调用。
- 记录每项数据的原始显示、来源和观察时间。账号信息保留粉丝量与简介，不采集或展示关注数、账号累计获赞与收藏；互动数据仅使用本条视频的指标，缺失值不写成零。
- 日期精度不足时保留原始显示，不猜年份或时分。账号定位若为推断，说明依据与样本范围。
- 交付来源链接去除访问令牌，输出和日志不包含登录凭据。

## 文案与画面

先校验视频时长、音轨和画面。调用可用的转写工具处理音频，保存片段起止秒数；分块时恢复全片偏移并去除重叠重复。不具备转写能力时不得根据标题补写原文。

分别记录音频逐字稿、画面字幕、白板文字和笔记正文。保留原始版本，校对不改变观点；不清楚的词标记听辨不清，专名修正保留依据。字幕与音频不一致时并列保留。按适用内容使用范围交付；用户已说明具有相关授权时，在本任务记录其说明并沿用，不重复要求证明，也不扩展到以后其他视频。无法提供全文时交付摘要、分析与必要短引文。

可以提供全文时，把逐字稿按本条内容分章并加时间码，合并进主报告，同时提供独立入口。机器转写未听校就保留“待校对”状态，不因阅读版要求简洁而伪装成核准稿。

按内容变化建立关键帧时间索引，重点核验开头、转场、关键内容和结尾。采样观察只支持相应粒度的段落还原；镜头边界未经核验时，不宣称逐镜头精确。无画面时不生成视觉脚本，无音频分析时不推断配乐和音效。

按时间对齐口播与画面，生成“成片还原脚本”，不称作作者拍摄前的原始脚本。记录画面、动作、字幕、声音、剪辑、段落作用，以及所用帧和转写片段。

## 分析与导出

生成报告前读取 [references/report-contract.md](references/report-contract.md)，按该规范记录覆盖情况、缺失项、时间码与证据。

分析覆盖八个角度：人群、选题价值、标题封面、开头钩子、结构、情绪表达、视听节奏、互动转化。每节使用“观察—可能的作用—可借鉴”分点，并配一张有依据的图表，不用图标或表情符号代替。重要结论关联时间段或评论证据，区分事实、作者自述与机制假设。

制作或修改图表前读 [图表规范](references/charts.md)。情绪部分默认使用覆盖全片的定性起伏折线：横轴为视频时间，纵轴用较低、中等、较高等文字标签，节点按实际内容段落设置。标明是叙事分析假设，不是观众情绪、语调检测或留存实测；不复用历史案例的波形、节点数和高低判断。

没有播放量不算播放口径的互动率，没有对照样本不宣称已验证爆款原因；评论样本不冒充全量统计。学习建议解释适用条件。用户要求改编时，用其自己的观点、经历和素材另写原创方案。

默认报告结构：核心结论、基础信息、文案梗概与段落脚本、八角度图表分析、学习应用、简短数据说明及适用的完整逐字稿。表格呈现数据和时间轴，短分点呈现解释。素材不足时说明缺失，不交付大片空表冒充完成稿，也不为凑齐图表捏造观察或数据。

阅读稿整理与打包前读 [报告整理与导出规范](references/report-delivery.md)。去除阅读稿中的内部证据 ID、HTML 注释、source segments、调试日志和代码块；原始证据与工具代码继续保留在内部。必要的数据日期、区间口径、抽样范围和文案校对状态不能删除。

本技能 `scripts/package_report.py` 可清理已编写的 Markdown 并打包为图片内嵌的单文件 HTML，无需额外 Markdown 库。它负责版式与打包，不代替助手分析或判断授权。八张图逐张查看，检查改图后 HTML 中内嵌的版本也已更新。

需要 DOCX、PDF 或其他格式时，使用当前环境中实际可用的对应文档工具和适用工作流；导出失败不影响已完成的文本产物，但需说明状态。

## 交付检查

- 时间码位于媒体时长内；字幕按时排序，无因分块造成的重复。
- 文案处理到全片并核查未覆盖区间后，才标为音频全文处理完成。
- 分镜与分析的观察粒度、遗漏范围和证据可见，不把单帧推及全片。
- 文案、元数据和视觉模块分别记录状态，缺少粉丝量不抹掉已完成转写。
- 确认文件实际存在后给出链接，简短说明完成内容与仍需补充的素材。
- 确认每个分析角度的图表、文案入口与全文覆盖；阅读文件中不混入内部标记。新增依赖、图表、缓存和输出继续保存在 D 盘。
