# 从拆解文档到本人文案、画面草稿与核对

## 一 交付拆解报告后，接收本人内容

先完成原报告与适用附件；同一任务已有报告则读取现稿接续。本人主题、素材和表达偏好若已在本次对话给出，直接沿用。

本人内容确实缺失时，用一个简短问题收集：**“你想做的视频讲什么？有哪些自己的经历、成果或可用素材？希望参考对标视频的哪些讲法？”** 平台、时长、出镜方式和已有账号定位能从上下文确定时不重复问。缺少核心主题或本人事实时保留报告与进度，不填作者成绩、不从别的账号或私人资料库自动借用个人事实。

收集结果保存为本人创作说明：

- 主题、想说给谁、希望观众看后知道或做什么。
- 本人实际经历、观点、成果、可公开文件或录屏；材料状态为已完成、计划或待确认。
- 参考侧重：讲述顺序、逐字稿的口语节奏、画面表达或组合；用户选定风格。
- 平台、预计时长、本人出镜或旁白、素材边界。

默认完整流程包含收集阶段，但不强迫只要求拆解的用户继续创作。用户更换主题时采用最新说明，不改变原视频证据。

## 二 方法对应本人素材，再写文案

从报告中选适合本条的少量方法，填写“原视频做法—证据—可借鉴方法—本人内容—可拍画面”。数量按内容需要，不凑固定个数。

**风格指令优先：**用户要求直接参考逐字稿时，读取实际稿件，参考开头方式、步骤连接、解释节奏和收尾方式；内容使用本人素材。不要自行换成基于本人稿件模拟分析得出的另一种结构。事实核对不等于重新选择目标人群或重写风格。

先确定每段任务，再交付推荐标题、封面文字、完整口播及笔记正文。口播单独保存，不夹入镜头指令；完整拍摄脚本中的口播与采用稿一致。草稿例句标为练习或计划，不声称已经发布或获得流量效果。

原视频已拍的时间码与本人拟拍时间分开。本人时长先估计，实际试读后校准；没有音轨时不生成假SRT或词级精确时间。

## 三 拍摄脚本必须包含可视画面草稿

先为每个镜头编号，填写：

| 字段 | 内容 |
|---|---|
| 镜头编号、拟时间或段落 | 本人视频的制作预算；允许尚未确定秒数 |
| 口播 | 采用稿的对应原文 |
| 画面与动作 | 本人位置、景别、录屏或素材、手势或点击 |
| 屏幕文字 | 实际准备显示的短文字 |
| 镜头运动与剪辑 | 固定、推近、局部放大、切换及其目的 |
| 声音 | 拟人声、配乐或音效，标为设计，不冒充已听到 |
| 素材与状态 | 本人素材路径或描述、已有／待录／待确认 |
| 画面草稿 | 实际输出的构图图像与镜头编号对应 |

**默认实际画草稿：**每个脚本镜头至少一张构图线框PNG，另有分页总览。画出人物区、信息区、标题／字幕区及关键动作标注，标“画面草稿·非成片”；不只交付“此处放截图”等文字。无需写实人物或复杂美术，优先用程序绘制草图。要精美风格图或需要编辑照片时，再使用实际可用的相应图像能力。

本技能的 `scripts/render_storyboard.py` 使用已有Pillow绘制PNG；无新增云服务。准备镜头清单JSON后运行。它会保存单镜头草图、总览和索引，以及含每张草图的脚本Markdown，可用 `package_report.py` 打包成图片内嵌HTML。绘制器不代写口播、不校验素材真实性；助手负责检查布局、隐私和最终语义。

### 镜头清单示例

下面仅说明数据结构，内容与数量随本次创作变化：

```json
{
  "title": "本人视频拍摄脚本",
  "shots": [
    {
      "id": "s01",
      "label": "成果开场",
      "timing": "拟0—8秒",
      "layout": "split",
      "speech": "这里填写采用稿的对应口播。",
      "on_screen": "这里填写屏幕重点字",
      "visual": "本人在左，右侧展示成果局部。",
      "motion": "先出成果，再切本人讲解。",
      "audio": "本人录音，配乐待选。",
      "asset_status": "本人待拍，成果录屏已有",
      "screen_label": "成果录屏／待补",
      "asset": null
    }
  ]
}
```

`layout` 支持 `talking_head`、`screen_demo`、`split`、`comparison`、`text_card`。`asset` 可省略或为空；提供时只选已核对、可公开的实际图片。无图时绘出标明内容的占位框，不伪造真实录屏。`comparison` 可填写 `before`、`after`，并注明两者是实际版本还是拟改稿。所有完整口播、动作和状态也保留在脚本表与索引中。

```powershell
& 'D:/codexfile/mySkill/video-breakdown/.runtime/python/python.exe' -X utf8 -B `
  'D:/codex_home/skills/video-breakdown/scripts/render_storyboard.py' `
  --input 'D:/任务/creation/storyboard.json' `
  --output 'D:/任务/creation/output/图文版/storyboard'
```

每张草图能在拍摄脚本中找到，主脚本包含总览与所有单镜头草图。草稿是原创视频的计划，与原视频关键帧严格区分。素材缺失先画示意并标待录，不把拍摄可完成状态写成已经拍摄。

## 四 核对、修正与交付

核对以下项目，并修改发现的具体问题：

1. 本人事实与来源吻合，未借用参考作者的经历、数据或成绩。
2. 用户选定的讲述风格仍被保留，结构调整有明确依据或用户要求。
3. 标题、封面、开头承诺在口播和画面中兑现；未验证效果不写成保证。
4. 口播采用稿、脚本口播、镜头索引、画面草稿编号和版本一致。
5. 画面支撑重要句子，“你看这里”有实际指向，草图文字可读，需补录与待确认项可见。
6. 未录音时不标精确时长或真实声画效果；用户提供录音后再对齐。

逐张查看导出草图与分页总览；修改图像后重打包HTML，核对内嵌的是最新版。草图查看通过不代表最终实拍画面、人声或发布表现已核验。

交付：**原创文案**（标题、封面、全文口播、笔记正文）、**拍摄脚本图文版**（表格＋分页总览＋逐镜头草图）、**素材待补与核对记录**。默认提供Markdown和自包含HTML；图片提供独立PNG。用户只需某些格式时遵从，但可视画面草稿仍需交付。

默认文件可放 `creation/` 下；与原拆解 `output/` 分开，避免重导出覆盖。文案修改保存下一版本。`creation.json` 单独记录本人说明、阶段状态、采用稿、草图清单、核对结果和待补项；不要把本人拟镜头写进原视频 `visual_segments`。当前CLI不自动管理此记录，由助手维护。

缺少本人核心内容时状态为待输入；图文脚本尚未绘图或未检查时不标完整流程完成。检查只处理相关问题，不自动重做原视频或生成新模拟报告。未经用户要求不发布、不向他人发送，也不改动公开仓库。
